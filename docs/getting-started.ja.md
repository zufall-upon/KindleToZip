## 現在の提供状況

**[Windows x64用Portable v0.1.6](https://github.com/zufall-upon/KindleToZip/releases/tag/v0.1.6)は2026-10-29から通常Release＋Latestとして一般公開中です。** 必須のソース検査・配布版の自作試料検査は成功済みです。利用者はローカルの画像改善を確認済みですが、従来のクリーンWindows・実書籍全冊報告はv0.1.2に対するもので、このホスト版EXEの結果ではありません。[検証履歴](validation.md)では利用者の報告と自動検査を区別し、過去の失敗も残しています。

Ubuntu 26.04では、導入済みZenityで匿名のZIP/CBZ保存先選択・取消を本人操作で確認し、表示も正常との本人目視報告を受領しました。nativeダイアログの画像は未提供・独立検査なしです。選択だけでは書き出されないことを確認したもので、ZIP/CBZ出力・内容照合は別の統合検査です。native pickerでの実出力や実Kindleの受入成功は意味しません。

### Linux x64の未公開ローカル試験バンドル

これはWindows v0.1.6 Portableとは別の**ローカル匿名試験候補**で、releaseや完全Portableではありません。現ソース・Node・事前に作成済みのdebug controller・Playwrightと固定revisionのブラウザ・自作試料だけを固定対象からコピーし、コンパイル、導入、ダウンロードはしません。不足や導入済み異版は停止します。`receipt.json` にベースcommit、未コミットを含むapp sourceのSHA-256、Node/Playwrightの版、controllerが既存debugでビルド出所未確認であること、各ファイルのハッシュを記録します。`SHA256SUMS.txt` はreceiptと起動スクリプトの照合用で、第三者による署名や改ざん防止の保証ではありません。

出力先は**既存でない新しいディレクトリ**にしてください。親は既存の実ディレクトリ（リンクでないもの）を指定します。以下は準備済みの今回専用ツリーを使う例です。容量は事前に測定され、出力先の空きがペイロード＋20%＋256 MiB未満なら作成前に停止します。中断時の不完全な出力を勝手に削除・上書きしないため、原因を確認して別の新規名を使ってください。

```bash
df -h / /srv/work /srv/archive
findmnt -T /srv/work
findmnt -T /srv/archive
/home/user/.local/bin/node scripts/build-linux-distribution.mjs --output '/srv/work/mobmate/kindletozip-linux-bundle-98eefa8d/配置 先 日本語'
cd '/srv/work/mobmate/kindletozip-linux-bundle-98eefa8d/配置 先 日本語'
sha256sum -c SHA256SUMS.txt
./start-linux-bundle.sh                 # 通常の操作画面
./start-linux-bundle.sh --self-check    # Snap所有の匿名試料1画面→Review→crop→ZIP
```

起動時に同梱ファイルのハッシュ・種類を検査し、欠落・変更・リンクを拒否します。引数なし、`--self-check`、Portable専用の `--login`、匿名だけの `--anonymous-profile-check` が固定入口です。`KTZ_USER_DATA_DIR`、`KTZ_CONTROLLER_PATH`、`KTZ_TEMP_DIR`、`PLAYWRIGHT_BROWSERS_PATH`、`NODE_OPTIONS` 等の外部上書きは拒否します。ソース開発用の `artifacts/linux-port/env.sh` を読み込んだシェルでは `unset PLAYWRIGHT_BROWSERS_PATH` してから起動してください。アプリのデータはバンドル内 `data/application`、self-checkは毎回新規の `data/self-check-…` に保存し、既存データを上書きしたり別の利用者領域にフォールバックしたりしません。self-checkの結果は匿名データとして残ります。PortableのSnap匿名所有readerは `data/owned-sample/` 内に新規専用profileを作り、正常終了後も残します。ソース実行は従来の `~/snap/chromium/common/kindle-to-zip-owned-sample/` を使います。一時領域はPortable内 `temp` とし、安全な所有・正常終了時清掃規則を使い、終了不明は保持します。従来の本人ログイン入口は変更せず、Portable専用の相対profileは別です。移行と制約は[Ubuntu Portable](ubuntu-portable.ja.md)を参照してください。

2026-11-02の匿名検査では、ホーム内の実Portable全体を同一FSで移動し、旧位置がない状態で公開入口から同じ匿名Cookie・相対ID・profileのdevice/inode・Reader相当の解決・通常sandboxを確認した後、元の配置へ戻しました。実デスクトップGUIでは匿名プレビューまで到達しましたが、所有ウィンドウの数値欄に対してAT-SPIの値設定が反映されず、有限承認以降のGUI全工程は未検証です。追加診断では終了確認が成立せず、匿名owner・lockと一時領域を保持しています。削除・強制終了・再利用せず検討待ちとし、Portableデスクトップ入口は旧候補に戻しました。self-checkの成功を配置GUIのZIP/CBZ全工程や実認証の成功と読み替えません。

Node、controller、操作画面用とheadless試料用のChromiumは同梱しますが、Linuxの共有ライブラリ、画面・Wayland、DBus、既存の通常保護付きCanonical Chromium Snapとその厳密な事前検査は同梱・回避しません。通常GUIで「匿名の自作試料」を選ぶ経路はSnapを使い、変更されたSnap、権限不備、personal init、所有や終了不明では従来どおり停止・保持します。保存先選択のZenityは導入済みの場合だけの任意機能です。特定ホストの匿名self-checkや通常GUI起動が、クリーンUbuntu、他ディストリビューション、実本・全冊・ページ順・アーカイブ品質、Windows互換の成功を意味するわけではありません。

```bash
export PLAYWRIGHT_BROWSERS_PATH="$PWD/artifacts/browsers"
export CARGO_TARGET_DIR="$PWD/artifacts/rust-target"
test -x "$CARGO_TARGET_DIR/debug/ktz-g02-controller"
npm run test:store
npm test   # 公開GUI起動検査にはX displayが必要。XvfbはWayland実機の代替ではない
npm start
```

controllerは `KTZ_CONTROLLER_PATH` で明示できます。PATH探索・自動ビルドは行いません。専用領域の不正な権限・所有者・種類・ハードリンクは修復せず停止します。同期不明や公開済み未記録の際は表示された保存先と保存領域を再起動後に点検し、再起動だけで整合性が保証されたとは扱いません。長い `TMPDIR` でChromiumのUnixソケットが作れない場合は、短いprivate一時領域を使用します。詳しくは[開発手順](development.md)を参照してください。

取得の承認欄で「今回の最大取得画面数」を正の整数で指定できます。上限は承認に結び付き、開始時の省略でも解除されません。空欄で承認した場合だけ従来の上限なしです。N枚の新規原本を確定したら、次の撮影・送りをせず点検へ止まります。白紙・重複・保存失敗などの安全停止は優先します。表示画面数であり、見開き分割後のページ数・実ページ範囲・全冊完了ではありません。停止時の最終画面は送らず残し、再開には再プレビュー・最後の画像との照合・再承認・別開始が必要です。再開で既存原本を照合して送る操作は新規確定数に数えません。上限は開始ごとの設定で、複数回の累計制限ではなく、ジョブへ永続保存もしません。

この一般向け有限停止の追加自体は、実本の撮影・保存・ページ送りの許可を意味しません。下記の個別許可を除き、匿名試料での検証と実サービス受入を分けます。限定的な一回の結果は下記のとおりですが、実サービスでの一般利用に向けた統合検証、現候補のWindows互換確認、Linux配布・通常利用の仕上げは引き続き未検証です。

別の匿名試験入口 `npm start -- --sample-owned-pipe` は、所有者が生成した標準自作試料と毎回新規の匿名profileだけを対象にします。URL・profileの指定や保存済み領域の再利用、実Kindleへの接続はできません。ジョブを作成し、補助操作の「匿名自作試料をLinux所有pipeで開く」から対象タブ・プレビューを選び、**正の有限画面数を指定して承認**した後、別操作で開始します。承認時に空欄は許されず、開始時の省略は承認上限の継承です。従来の自作試料では空欄＝上限なしの互換動作を維持します。

この匿名入口は所有者が固定した匿名のASIN相当値と表題を、実際に開いている試料ページのrouteと表題に照合します。同じ表題でも別のASINは拒否し、別対象への一時変更・document変更も復元後に失効したままです。同じ内容の表題再描画は許します。照合は取得許可ではなく、プレビュー後の有限上限承認と別の開始操作を省略できません。

所有者は通常保護のSnapをprivate pipeで起動し、実プロセス・グループの終了と所有identityを照合してから自分のlockを解除します。匿名profileは通常終了後も残ります。終了が不明な場合は成功にせず、所有者・pipe・lockと一時領域を保持します。手動削除や強制終了を正常終了の代わりにしないでください。対象・位置・documentの変化や送りの応答不明では追加操作を停止し、不明な送りは再送しません。匿名試験の成功は実本の取得許可・実サービス受入を意味せず、他アプリやOS画面全体の非干渉・非遮蔽も保証しません。

所有pipeの終了要求は、lock解放の許可送信と所有者の終端待ちを含め12秒で打ち切ります。ブラウザの終了自体が不明な場合は従来どおりowner・pipe・lockを保持します。ブラウザとグループの終了確認後、lock解放の完了だけが確認できない場合は内部で `owned_pipe_release_unconfirmed` と区別します。この段階はlockが既に解放済みの可能性があり、保持済みと断言しません。いずれもアプリの終了成功にはせずprofile・親一時領域を保持し、再利用しません。遅れて届いた正常通知や再度の終了操作だけで成功・自動削除へ切り替えず、lockの再作成や強制終了もしません。

専用ブラウザを先に通常終了した場合も、その所有者の終了確認を保持し、アプリから終了するときに一回だけlock解放を認可します。所有pipeではPlaywright接続の切断と期限付き終了をCDPの後片付けより先に行い、応答のないdetach待ちで期限の開始を妨げません。

起動診断は既知のcontroller・専用領域・排他・操作画面の失敗を区別します。長い一時パスが疑われる場合も原因を断定せず、短いprivateディレクトリを `KTZ_TEMP_DIR` へ明示指定してください。固定文字数での拒否、自動退避、権限修復、ブラウザ再取得はしません。

### Linux の専用ログイン入口

`app/linux-login.mjs` は取得用Application、Reader、操作サーバーとは独立し、日本の公式入口 `https://read.amazon.co.jp/` を専用Chromiumウィンドウで開きます。引数でURLやプロファイルを指定できません。ログイン・追加認証・選書は本人が行い、この入口から撮影や取得は始まりません。Linuxの実Kindle一般取得は未対応のままです。

準備済み環境ではデスクトップの **KindleToZip ログイン** を開きます。Node、プログラム、作業ディレクトリはショートカットに固定されています。CanonicalのChromium Snapを通常のsandbox・Snap confinement・デスクトップの鍵管理サービスで使い、個人の既存ブラウザプロファイルは使用しません。

専用領域は `~/snap/chromium/common/kindle-to-zip-login/owned/profile` で、Snapのリビジョンとは独立しています。通常終了時も削除せず、所有情報、権限、ディレクトリのidentityと排他を確認します。別起動中や起動・終了を確認できない場合は再利用を拒否し、領域と排他情報を保持します。エラー時にこれらを削除・移動・再生成せず、安全を確認できるまで使用を保留してください。

既存個人設定の移行やinitの読込みを避けるため、確認したSnap wrapperと権限状態を起動前に確認します。`~/.chromium-browser.init` が存在する場合は、種類にかかわらず中身を読まず停止します。シンボリックリンクは、切断済み権限だけでは読取りを防げない場合があるためです。Snapの更新、設定や権限の変更、Snap共通領域の状態変化などで確認できなくなった場合も安全側に停止し、再検証が必要です。匿名データによる暗号保存・再起動試験は、実際のAmazonアカウントでのログイン成功を意味しません。アプリが領域を消さなくても、サービス側の期限やログアウトなどで再認証が必要になることがあります。

### Linux の取得しない表示確認（試験段階）

通常のログイン専用ショートカットとは別に、`app/linux-inspect.mjs` は同じ既存の専用プロファイルと固定の日本公式入口を使い、本人が選んだ画面の書名・位置スライダー値・表示領域寸法を**一回だけ**確認します。新規プロファイルの作成、別のブラウザへの接続、URLやプロファイルの指定はできません。取得機能とは接続せず、撮影、保存、ページ送り、本の自動選択は行いません。実認証プロファイルで使う前に、匿名検証と独立Reviewが必要です。実書籍での成功はまだ確認していません。

以下は従来の手動試験入口の識別用であり、再実行の依頼ではありません。この入口は確認ダイアログと本人の選書・終了操作に依存し、実本では対象を一件にした条件でも既知マーカー判定が不成立でした。同じ選書・本棚閉鎖・位置バー表示・確認ボタンを繰り返し依頼する運用は停止しています。実認証ブラウザを勝手に開き直さず、技術側の匿名検証を先に行います。出力に必要な書名などが含まれる場合も公開せず、パスワード・認証コード・Cookieを送らないでください。

```bash
/home/user/.local/bin/node app/linux-inspect.mjs
```

開いているタブが複数、対象やマーカーが不明・複数、認証画面・本棚・モーダル、別originなどの場合は成功にせず停止します。中止する場合はダイアログで **確認せず終了** を選び、ブラウザを通常終了します。ブラウザを先に閉じた場合も観測せず、所有した確認ダイアログだけを閉じます。使用中や起動・終了が不明なら排他情報を削除せず保留してください。起動時に公式入口を開くため、サービスの復元や遷移によって以前の選択状態が変わらない保証はありません。この確認はDOMの寸法であり、実画像の内容や、ウィンドウが他の画面に覆われていないことの証明ではありません。

不成立時は、通常終了を待った後、固定案内に続けて `表示確認の診断: {"stage":"…","reason":"…"}` を起動元へ出します。段階と理由は固定語彙だけで、本文・アカウント情報・URL・通信の生データ・例外の詳細は含めません。たとえば `confirmation` は確認操作、`target-selection` は対象タブの判定、`metadata` は既知表示マーカーの確認段階です。ダイアログの異常終了は本人の取消と区別し、表示失敗との区別に必要なstderrは有無だけを使い、内容を復号・保存しません。終了案内の表示失敗も成功結果にはしません。`reader-markers` はマーカーの不足・重複・不可視などの総称であり、特定の画面状態を断定しません。中止の案内だけで「確認ボタンを押していない」とは判断できません。過去の固定案内しかない失敗の原因は、この追加で遡って確定できません。不明な画面を本文読取りで調べたり、拒否条件を緩めたり、自動で再試行したりはしません。

現在の内部probeは既知の `identity`・`position`・`next` ごとに `missing`・`multiple`・`hidden`・`clipped` を区別します（例：`reader-identity-clipped`）。件数は `none/one/multiple`、可視性は固定分類だけを返し、準備状態のprobeでは書名や位置値を読みません。metadataモードも従来の一意性・完全可視性・DIV祖先・描画面の条件を通過した場合だけです。Playwrightの `isVisible()` だけでclipを許可せず、未知のiframeやDOMを探索して代替対象を探しません。過去の `reader-markers` 記録から個別原因を遡って確定することはできません。

`observeBoundKindle` は、呼出元が別途確立した本人選択とpage/frameの対応を毎回検証できる場合だけ、入力を送らず有限時間の準備待ちを行い、metadataを一回読む内部部品です。別の候補へ切り替えず、対応失効・重複・期限超過で停止します。匿名fixtureの不透明な選択tokenで反証試験を行いますが、通常終了した実セッションに同じbindingが存在する証明ではなく、現実の公開入口へ自動選書や自動確認として接続していません。

## 導入と起動

各コマンドを順番に実行し、失敗したら止めてください。チェックサム不一致・ビルド失敗・テスト失敗を無視して先へ進めないでください。インストーラーはコントローラーの依存物を取得するため、続けてランチャーの依存物を明示取得します。既存スクリプトの使い方の説明であり、スクリプトの動作変更ではありません。

```powershell
git clone https://github.com/zufall-upon/KindleToZip.git
cd KindleToZip
npm ci --ignore-scripts --no-fund --no-audit
./scripts/install-rust.ps1 -FetchDependencies
& ./artifacts/toolchains/cargo/bin/cargo.exe fetch --manifest-path poc/launcher/Cargo.toml --locked
node scripts/install-browser.mjs
node scripts/install-browser.mjs --headed
pwsh -NoProfile -File scripts/test-rust.ps1
npm start
```

Rustインストーラーと直後の `cargo fetch` は同じPowerShellセッションで行い、専用環境の設定を引き継ぎます。Windowsの実行ポリシーでスクリプトが止まる場合は、内容と組織のポリシーを確認し、セキュリティ設定を全体で無効にしないでください。

専用ブラウザのウィンドウにローカル操作画面が開きます。画面を閉じるか、起動したターミナルでCtrl+Cを押すと通常終了します。コントローラーのEXEが使用中なら、上書きビルドや無関係なプロセスの終了はせず、自分のアプリを通常終了してから再ビルドするか、別のソース配置を使ってください。

## 実書籍なしで試す

1. **「決定・次へ」** で新しい作業を用意します。
2. 専用セッション・自作試料の補助設定を開き、**自作試料**を選びます。
3. 試料の読書タブを選び、プレビューを確認してチェックし、承認します。**承認だけでは取得しません。**
4. 別の操作で明示開始し、停止後に保存画像を点検してから出力します。

試料は自作の図形と文字です。成功しても、現在のKindle・全レイアウト・全冊取得への対応を証明するものではありません。ログイン画面を取得対象にしないでください。

## Kindle Webで使う

1. アプリから専用Kindleブラウザを開きます。本人が**公式画面で**ログイン・追加認証を行い、1冊を開いて開始位置を調整します。
2. アプリへ戻り、本棚ではなく実際の読書タブを選びます。v0.1.6では選択した日本・米国・英国のKindle Webを開きます。対応するKindleプリセットを試し、必要なら取得領域・本の識別・位置・次へボタンを手動指定します。
3. プレビューの本・範囲・方向・位置を確認します。承認後、別の操作で明示開始します。対象不明・認証状態の変化・送りの不確実性などで停止する場合があります。
4. 停止後に画像の採用・除外・順序・クロップ・任意の見開き分割を点検します。取得やプレビューの停止後も確定保存画像は出力できます。アーカイブの検証成功は全冊取得を意味しません。

主操作は **「決定・次へ」「キャンセル・前へ」「終了・最初から」** です。画面の次操作に従ってください。3工程は、3クリックで完了するという意味ではありません。言語メニューで日本語・英語・簡体字中国語を選べます。現在のソースCIでは公開言語切り替え検査も成功しており、過去の失敗と配布版検査の範囲は[検証記録](validation.md)で区別しています。

### v0.1.6の地域選択・余白比較

専用ブラウザを開く前に「Kindle利用地域」で日本・米国・英国を選択します。表示言語とは独立し、アプリ起動時の初期値は日本です。地域を変えるには取得を止めて専用ブラウザを閉じ、地域選択後に対象タブ・プレビュー・承認・別操作での開始をやり直してください。公式入口の確認と匿名試料による境界検査は、各地域の実書籍成功とは別です。

画像点検で対象を選び「選択画像の余白を検出」から白・黒の余白候補を原本と比較できます。本文・枠・ページ番号を確認して適用してください。取消だけでは保存状態を変えず、手動crop・原寸へ戻す操作も残ります。候補がない場合もあり、JPEG適用時は取得時の画質で再圧縮します。これらはv0.1.6 Portable版に含まれます。[ストア拡張計画](store-adapters.md)の3社も未対応のままです。

## 画像・保存データ・プライバシー

v0.1.6では取得前に「取得画像の形式」とJPEG画質（1〜100）を選べます。JPEGは取得時に圧縮され、クロップ・分割でも再圧縮されるため、画質と容量をプレビュー・点検して選んでください。取得済み原本のバイトは変更しません。点検画面で画像ごとに1枚／2枚と読み順を修正し、余白を手動クロップできます。「全原寸へ戻す」は原本を使い直します。余白候補は比較と明示適用が必要で、無断で適用しません。判定・写り込み対策は完全ではないため、出力前に本人が確認してください。

- 標準・2倍の描画密度は表示の描き方を変えるもので、元にない細部を復元しません。画像ごとの **16メガピクセル・32 MiB** は安全上の上限であり、有料の制限ではありません。
- 見開き分割は任意です。右→左・左→右を選び、結果を点検してください。内容を意味的に認識する機能ではありません。除外・クロップでも原本を保持し、既存の出力は上書きしません。
- 開発版の作業データ・専用プロファイルは、別のローカル作業先を明示指定しない限り `artifacts/mvp-data/` に置きます。PortableビルドはEXE横に `runtime/`・`data/`・`temp/` を作成します。
- **ログイン状態の保存は既定ONです。** OFFでは別の一時プロファイルを作り、通常終了で削除しますが、異常終了時は残る場合があります。保存済みプロファイルは同じPC・Windows利用者での再利用が前提で、Amazonの失効・再認証要求は回避しません。
- Cookie・プロファイル・書名・画像・出力アーカイブは非公開で扱い、フォルダを公開の不具合報告に添付しないでください。安全消去や、管理者・同じWindows利用者からの秘密保持は保証しません。
- 公式の読書・認証通信と初回取得はネットワークが必要です。アプリ独自のテレメトリ・自動更新確認・支援ページへの自動アクセスはありませんが、公式サービスやChromiumによる追加通信はあり得ます。オフライン動作・通信隔離の保証ではありません。

[セキュリティと通信の詳細](security-and-trust.md)（英語）、[検証記録](validation.md)（英語）、[法的注意事項](legal-notes-ja.md)を参照してください。DRMを解除しなくても、Amazon規約や著作権への適合は証明されません。非公式アプリであり、GPLv3は書籍内容の再配布を許諾しません。

## うまく動かないとき

不明な対象や黒いプレビューで開始を繰り返さず、停止して既存画像を保持し、画面の次操作に従ってください。[既知の検証失敗](validation.md)（英語）を先に確認してください。文書で不具合が直るわけではありません。報告には認証情報・書名・書籍本文・個人パスを含めないでください。
